## K230 二维码串口

### K230 黑色物块停车测试

只需要无线画面和阈值调试时，先将 `K230/wifi_config.example.py` 复制为本地 `wifi_config.py` 并填写Wi-Fi信息，再上传 `K230/避障无线预览.py`、`K230/obstacle_detection.py`、`K230/obstacle_web.py` 和 `K230/wifi_config.py`，详见 `K230/K230无线预览说明.md`。账号密码不提交到仓库。通过USB上传并启动后，电脑浏览器打开终端打印的URL；这个独立预览不启用UART、不控制车辆。

先将 `K230/避障停车.py` 和 `K230/obstacle_detection.py` 一起上传 K230，单独运行 `避障停车.py`，不要同时运行扫码脚本。默认 `UART_STOP_ENABLED=False`，不初始化串口、不通知STM32，可只给K230供电并通过USB CanMV IDE查看检测框与像素位置；确认后显示 `CONFIRMED`，不代表车辆停车。不属于 MaixCAM 安装包。有线预览使用 `img.compress_for_ide(quality=70)`，每帧完成检测框和红线绘制后直接发送给IDE，不初始化Display虚拟屏幕。

联调停车时将 `UART_STOP_ENABLED=True`，重新编译并烧录STM32固件，串口接线沿用上面的 UART1 → USART3。无线调试前可先通过USB运行 `k230_debug_info.py`，记录SYSTEM、PYTHON和MODULE输出，并记录电脑端IDE版本；该脚本不会初始化摄像头、串口或连接Wi-Fi。`Display.VIRT`本身不是无线图传，需要另行确认固件支持的网络调试/图传方式。

本阶段仅做像素定位和可选停车，没有毫米坐标、测距或路径重规划。默认ROI为640×480画面的下方2/3，即(0,160,640,320)，上方1/3不参与识别，坐标仍以完整画面为基准，LAB阈值沿用bizhang.py，有线预览最低黑色像素数默认2200（无线默认5000，可在网页调整），find_blobs的像素和包围框面积预筛选均使用同一门槛；从有效色块中选择像素数最大的一个，不设面积上限。首次检出位置作为稳定窗口锚点，中心各轴偏差不超过40像素，连续3帧确认；漏检或中心超限会重新确认。启用串口时确认后发送精确ASCII行 `OB:STOP\n`，每200ms重复发送，界面 `STOP TX` 只代表发送状态，不代表STM32已经确认停车；独立预览只输出检测日志。显示中心u/v、包围框底部行和黑色像素数，底部行只是预览估计，不能当作标定后的地面接触点。

STM32在USART3中断内识别完整停车行，立即设置现有急停请求；由主循环执行停车、取消动作/路线、清除排队的上位机指令并解除授权，输出 `OBSTACLE STOP; black blob detected; disarmed`。不会自动继续；移走物块后仍需重新授权并发起动作。QR行和含有OB:STOP文字的二维码不会触发障碍停车。该消息没有确认回包或校验和。

验证顺序：先架空核对电机方向、急停和接线，用黑物块观察CANDIDATE→STOP TX以及主控停车日志；移走后确认不自行恢复；再用实物地面、灯光与阴影调整BLACK_THRESHOLD、ROI和MIN_PIXELS，最后低速短程测试停车距离。摄像头断开、程序退出或未识别时不会主动停车，这不是通信失联保护。检测区域内任意合格黑块都可能触发，面积最大也不代表最近；固定前向摄像头不覆盖侧向和后方运动。未经实测不能用于自主比赛。

离线检查：`python -m unittest discover -s test/mecanum_jog/camera_code/K230 -p 'test_*.py'` 和 `powershell -File test/mecanum_jog/tests/test_obstacle_runtime.ps1`；C解析测试为 `tests/test_obstacle_stop.c`。

K230 发现二维码后发送 `QR:<UTF-8内容>\n`，内容最长 48 字节，换行和控制字符替换为空格；首次识别到可发送内容后仅发送一次，按115200/8N1留出本行发送时间后退出识别循环，不等待主控确认。随后依次停止sensor、关闭Display、等待100ms释放媒体缓冲，再释放MediaManager和UART；这是软件停止采图及显示，K230整板仍供电。下次扫码需重新运行脚本或重新上电。STM32 验证行格式后在蓝牙串口输出 `QR RESULT value=<内容>`，上位机“场地定位”页显示结果。二维码使用完整四组 `CCC+PPP+CCC+PPP`（例如 `156+123+516+231`）。完整任务在二维码点至少停车1秒，并采用本次已缓存的首个合法四组扫码结果（可在按键启动前或行驶途中收到）；未收到时继续等待，以该码决定两轮颜色顺序和放置位置；非法内容继续等待，不使用上位机预先下发的任务码作为后备。PC9可在上电后独立启动，不要求连接上位机。

将本目录全部文件部署到MaixCAM，运行 `main.py`。默认使用MaixCAM2 UART4：A21/TX、A22/RX、9600 baud；分别交叉连接STM32 PC11/UART4_RX、PC10/UART4_TX，并共地。若实际板型引脚不同，只修改 `vision_settings.py` 的设备和引脚映射。

正式程序在圆环模式使用640×480，物料模式使用320×240，收到模式切换请求时调整摄像头分辨率。圆环先进行3×3高斯滤波及非锐化掩模，再使用21×21邻域的自适应反向二值化。协议中的ROI、锚点、返回圆心和直径仍以320×240为坐标基准：圆环检测时放大ROI，检测后换算回原坐标；画面标记同步放大。现有STM32标定参数无需因坐标单位变化而修改，但切换分辨率后的视野与识别耗时须实机确认。

普通圆环检测仅接受 `target=2`。先检测同心圆环，再由 `ring_digits.py` 识别中心白色区域的1/2/3，只保留数字2对应的圆环，返回圆环中心。第二轮码垛的例外见下文v1.0.10：跳过数字识别，优先对齐圆环。没有2、存在多个2或字形匹配不明确时返回无效结果；不按左右顺序推断编号。模板包含用户提供实物照片的字形及OpenCV字体，支持旋转方向和倾斜。`RING_DIGIT_ROI_RATIO`、最低匹配分数及分数差在 `vision_settings.py` 中设置；分数是模板匹配指标，不是识别正确率。已用实物照片及合成图离线检查，摄像头视角、透视、遮挡和设备耗时尚需实机验证。

重新打包相机应用时必须包含 `ring_digits.py`，加上原有 `main.py`、`vision_detectors.py`、`vision_protocol.py`、`vision_settings.py` 共五个文件；`app.yaml` 已更新。比赛流程继续请求2号环；物料规则变更须配套更新STM32。手动请求1/3号环将得不到有效结果。

正式程序将B25配置为GPIO并保持低电平，板载补光灯在物料及圆环模式均关闭；正常退出或识别循环运行异常时再次输出低电平。普通数字圆环模式将相机对比度设为80，返回结果后及连续相同圆环请求之间保持；第二轮无数字圆环模式使用进入圆环前读取的物料对比度，以保持颜色辅助选环的原图像条件，切回物料备用时也恢复该值。两种圆环模式之间直接切换时更新对比度，不重复切换640×480分辨率，不写死物料对比度。MaixCAM2的物理引脚名为 `B25`，GPIO功能名和GPIO构造参数均为 `GPIOB25`，已与[官方引脚映射源码](https://github.com/sipeed/MaixCDK/blob/main/components/peripheral/port/maixcam2/maix_pinmap.cpp)核对；[GPIO说明](https://wiki.sipeed.com/maixpy/doc/en/peripheral/gpio.html)中的MaixCAM2示例名称与该源码不一致，不能照抄。对比度读取与恢复使用[官方相机接口](https://wiki.sipeed.com/maixpy/api/maix/camera.html)中的 `constrast()`。

程序只响应STM32请求，不主动发送运动命令。每个请求先丢弃2帧。取料物料（mode=1、target=0）要求连续10个有效帧，整个窗口横纵中心波动分别不超过8px，同时前5帧与后5帧的中心中位数在横纵两轴分别相差不超过2px；不再要求持续500ms，返回这10帧中心的中位数。颜色切换、目标丢失、采图为空、波动超限或前后中位数偏移超限后重新计数，每次新请求独立确认。圆环要求至少3帧、180ms、2px；第二轮码垛优先请求圆环，检测失败后的中间指定颜色物料备用（mode=1、target=2）保持至少5帧、500ms、2px并返回当前中心。物料请求1200ms、圆环请求1000ms内未稳定则返回无效结果，主控通信超时仍为1800ms。

正式相机和STM32均取消物料质量门槛。q字段保留原来的像素占比计算，仅用于诊断；圆环仍要求q≥60。物料有效标志只依据成功检测与静止判断，主控仍检查实际颜色、稳定标志和token。

正式物料检测采用用户提供的《物料.py》六组LAB阈值，见 `vision_settings.py`。每种允许颜色先取 `blob.area()` 最大的色块，再检查1500～30000的面积范围，以 `cx()/cy()` 为本帧中心；保留find_blobs的area_threshold=50、pixels_threshold=50及主控请求ROI。删除ROI贴边和锚点距离筛选。不限颜色时从各颜色合格结果中选面积最大的，面积相同时按颜色编号顺序选择，不再因多个颜色同时出现而拒绝。颜色编号仍为1红、2黄、3蓝、4绿、5黑、6浅蓝。

标定步骤：

1. 架空验证车体前后、左右方向，确认急停有效。
2. 分别对物料和三个物理圆环设置不会互相重叠的ROI与目标锚点。
3. 在中心、上下左右和四角至少九个位置记录像素误差及车辆实际毫米偏差。
4. 拟合 `forward_mm=a*du+b*dv`、`right_mm=c*du+d*dv`。
5. 将ROI、锚点和矩阵写入上级目录 `vision_config.h`，最后才把对应 `calibrated` 置1。
6. 先用5mm人工点动验证符号，再从小偏差开始自动闭环测试。

固定30字节帧定义见 `vision_protocol.py`。CRC为CRC-16/CCITT-FALSE，测试向量 `123456789 → 0x29B1`。

## 黑色圆环中心抖动测试

直接在 MaixVision 中打开并运行 `ring_jitter_test.py` 即可。脚本内置当前车辆的
圆环检测与稳定判定，不依赖其他项目文件；也可上传到 MaixCAM2 单独运行。
不要同时运行车辆视觉 `main.py`；测试程序不打开串口，不发送运动指令。

1. 固定相机和圆环，修改脚本顶部 `ROI`，使区域只包含一个完整圆环靶标，
   `ANCHOR` 放在该区域内。复现车辆问题时使用车辆实际请求的 ROI。
2. 自动按0%、20%、40%、60%占空比测试补光，使用B25/PWM6，PWM6不能同时用于A30。
   每档等待2秒再采集10秒，各档重新清空窗口；完成约需48秒，正常退出时关闭灯。
3. 全程固定相机、圆环和环境光。红色十字为原始中心，黄色十字为最近500ms
   有效连续检测的中心中位数，绿色圆为通过筛选的轮廓。
4. 屏幕 `old_stable` 使用现有2px、至少5帧、至少180ms的原始稳定条件。
   `span` 是最近500ms窗口各轴最大值减最小值；窗口丢失目标后清空。
   窗口未满500ms时也显示统计值，不能仅凭这个值确认稳定。
5. 每档结束输出 `RESULT light=...`，包含帧数、有效率、满足原始稳定条件的帧数
   及占比、中位数、各轴波动范围和总体标准差。先比较有效率和稳定帧占比，
   再比较波动；完全无有效目标时会明确提示。当前目录生成 `ring_jitter.csv`，
   每次运行覆盖，需先保存旧文件。
   CSV逐帧记录亮度档位、档内采样时间、坐标、有效状态、轮廓数、候选靶标数、轮廓半径和中心、原始稳定
   判定及500ms窗口统计。无有效中心时坐标和统计字段留空。

静止时若坐标突跳与轮廓数量/半径变化同步，重点检查轮廓切换；若长期只有
小幅随机抖动但 `old_stable` 很少成立，再根据实测噪声及允许的定位误差调整
圆环专用容差。多个候选靶标导致 `valid=0` 属于识别歧义，不代表物料移动。
每档总体统计只统计有效中心，需结合有效率判断，不能把丢失检测当成稳定。

## 历史物料检测预览（未同步v1.0.9）

这些独立脚本保留旧阈值、质量筛选和稳定规则，不能代表v1.0.9正式检测；验证新规则请运行main.py并接入主控请求。停止正式应用后，在MaixVision中直接运行 `material_preview.py`。此脚本内置当前正式检测逻辑、稳定判定和六色阈值，不依赖旁边的Python文件，不打开串口，不发送动作。后续修改正式阈值时需同步修改本脚本的 `COLOR_THRESHOLDS`。默认持续检测全部六色，画面标出颜色、圆形识别框、当前中心、质量和稳定状态；底部保留最近一轮结果。

脚本模拟物料请求：每轮丢弃2帧，1200ms超时，随后自动开始下一轮。测试稳定判定已改为容忍短暂漏检：只统计有效中心，保留最近500ms窗口及边界前一个有效样本，至少5个有效样本且首尾跨度≥500ms；横纵坐标范围都须满足容差。无效帧不能确认稳定，连续丢失超过 `MAX_MISSING_MS=200`、颜色切换或坐标超限时重新计时。`TARGET=0` 使用8px容差和中心中位数；1～3使用2px容差。`valid` 表示中心稳定，`usable=1` 还要求达到该颜色的最低q：黑30、红/黄/蓝/绿/浅蓝60，可在 `MIN_QUALITY` 中调整。画面与终端显示当前q和门槛min。分颜色质量门槛已同步到正式相机程序及STM32；漏检容忍仍仅在预览脚本中。通过顶部 `COLOR`、`COLOR_MASK`、`ROI`、`ANCHOR` 设置与STM32请求相同的条件；默认ROI是全画面。此预览不验证UART通信或整车动作。

## 历史六色物料诊断（未同步v1.0.9）

在MaixVision中单独运行 `material_jitter_test.py`，无需其他项目文件。
补光始终关闭，默认 `COLOR=0` 同时检测六种颜色；可改为1红、2黄、3蓝、4绿、5黑、6浅蓝以单独测试。脚本保留历史阈值，未同步本次正式应用修改。
设置与正式请求相同的 `ROI` 和 `ANCHOR`，只包含一个完整物料；白色采样框
必须完全位于物料表面，避开背景和高光，否则LAB统计没有参考意义。
启动预热2秒后持续识别，每10秒输出统计并清空本轮采样记录。可逐个更换物料，通过MaixVision停止按钮退出；不打开串口，不发送动作。

检测条件与正式物料算法一致。绿色框为候选色块，红色框为被过滤色块，
黄色十字为唯一候选中心，框旁标注颜色名称。全颜色模式下，多个物料或同一物料被多组阈值命中均判为歧义；颜色切换重新计时。输出有效率、稳定帧数、同时稳定且质量≥60的
可用帧比例、中心波动、质量值和采样框LAB均值的中位数。
`none`/`ambiguous` 为无候选／多候选帧数；`low_quality` 为唯一候选质量<60
的帧数；`area`/`clipped`/`outside` 为面积／ROI截断／锚点距离过滤的色块数。
诊断脚本的 `stable` 保留原2px、500ms条件；正式取料已放宽至8px，诊断结果不能直接等同于正式取料的稳定判定，仍须结合有效率和质量判断。
脚本只用于诊断，不会自动修改正式阈值；中心统计仅包含有效检测帧。

## 最大物料校准与指定颜色取料（v1.0.9）

主控物料请求selector=0表示不限颜色；`values[6]` 为允许颜色位掩码，颜色N对应位N-1，0表示检测全部支持颜色。两轮路线每批首次对准发送selector=0、掩码47（0x2F），只在红、黄、蓝、绿、浅蓝中选择最大面积物料，黑色不参与这一步；对准完成后请求切换为当前任务指定颜色和对应单色掩码。selector=1～6仅检测指定颜色。同色多个色块仍只取最大的。
