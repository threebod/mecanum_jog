# MaixCAM 车辆视觉微调

## K230 二维码串口

在 K230 CanMV 上单独运行 `扫码.py`，与本目录的 MaixCAM `main.py` 分别用于扫码和物料/圆环对准。K230 IO9 配为 UART1_TXD，接 STM32 PB11/USART3_RX；K230 IO10 配为 UART1_RXD，接 STM32 PB10/USART3_TX；两板共地，并核对实际板卡的 IO 电平。串口为 115200、8N1。

K230 发现二维码后发送 `QR:<UTF-8内容>\n`，内容最长 48 字节，换行和控制字符替换为空格；持续识别同一内容时约每秒重发一次。STM32 验证行格式后在蓝牙串口输出 `QR RESULT value=<内容>`，上位机“场地定位”页显示结果。扫码结果目前不决定物料顺序，`route mission` 在二维码点仍至少停车 1 秒，到时继续路线；取料顺序由上位机下发的四组任务码决定，不使用扫码排序。

将本目录全部文件部署到MaixCAM，运行 `main.py`。默认使用MaixCAM2 UART4：A21/TX、A22/RX、9600 baud；分别交叉连接STM32 PC11/UART4_RX、PC10/UART4_TX，并共地。若实际板型引脚不同，只修改 `vision_settings.py` 的设备和引脚映射。

正式程序使用B25/PWM6、100kHz PWM，首次收到圆环识别请求时将板载补光灯开启至20%占空比，返回结果后及连续圆环请求之间保持开启；收到物料识别请求时关闭。启动时保持关闭，正常退出或识别循环运行异常时也设为0%。当前协议没有离开圆环区通知，因此灯光通过识别模式切换控制。PWM6不能同时用于A30。

程序只响应STM32请求，不主动发送运动命令。每个请求先丢弃2帧，再要求至少5帧。取料物料（mode=1、target=0）要求持续500ms、每轴整个窗口中心波动不超过8px，返回中心中位数；颜色切换或丢失目标重新计时。圆环要求180ms、2px；第二轮暂存2号环上的第一批物料（mode=1、target=2，颜色由任务码决定）保持500ms、2px并返回当前中心。物料请求1200ms、圆环请求1000ms内未稳定则返回无效结果，主控通信超时仍为1800ms。

标定步骤：

1. 架空验证车体前后、左右方向，确认急停有效。
2. 分别对物料和三个物理圆环设置不会互相重叠的ROI与目标锚点。
3. 在中心、上下左右和四角至少九个位置记录像素误差及车辆实际毫米偏差。
4. 拟合 `forward_mm=a*du+b*dv`、`right_mm=c*du+d*dv`。
5. 将ROI、锚点和矩阵写入上级目录 `vision_config.h`，最后才把对应 `calibrated` 置1。
6. 先用5mm人工点动验证符号，再从小偏差开始自动闭环测试。

固定30字节帧定义见 `vision_protocol.py`。CRC为CRC-16/CCITT-FALSE，测试向量 `123456789 → 0x29B1`。

## 黑色圆环中心抖动测试

直接在 MaixVision 中打开并运行 `ring_jitter_test.py` 即可。脚本内置当前车辆的
圆环检测与稳定判定，不依赖其他项目文件；也可上传到 MaixCAM2 单独运行。
不要同时运行车辆视觉 `main.py`；测试程序不打开串口，不发送运动指令。

1. 固定相机和圆环，修改脚本顶部 `ROI`，使区域只包含一个完整圆环靶标，
   `ANCHOR` 放在该区域内。复现车辆问题时使用车辆实际请求的 ROI。
2. 自动按0%、20%、40%、60%占空比测试补光，使用B25/PWM6，PWM6不能同时用于A30。
   每档等待2秒再采集10秒，各档重新清空窗口；完成约需48秒，正常退出时关闭灯。
3. 全程固定相机、圆环和环境光。红色十字为原始中心，黄色十字为最近500ms
   有效连续检测的中心中位数，绿色圆为通过筛选的轮廓。
4. 屏幕 `old_stable` 使用现有2px、至少5帧、至少180ms的原始稳定条件。
   `span` 是最近500ms窗口各轴最大值减最小值；窗口丢失目标后清空。
   窗口未满500ms时也显示统计值，不能仅凭这个值确认稳定。
5. 每档结束输出 `RESULT light=...`，包含帧数、有效率、满足原始稳定条件的帧数
   及占比、中位数、各轴波动范围和总体标准差。先比较有效率和稳定帧占比，
   再比较波动；完全无有效目标时会明确提示。当前目录生成 `ring_jitter.csv`，
   每次运行覆盖，需先保存旧文件。
   CSV逐帧记录亮度档位、档内采样时间、坐标、有效状态、轮廓数、候选靶标数、轮廓半径和中心、原始稳定
   判定及500ms窗口统计。无有效中心时坐标和统计字段留空。

静止时若坐标突跳与轮廓数量/半径变化同步，重点检查轮廓切换；若长期只有
小幅随机抖动但 `old_stable` 很少成立，再根据实测噪声及允许的定位误差调整
圆环专用容差。多个候选靶标导致 `valid=0` 属于识别歧义，不代表物料移动。
每档总体统计只统计有效中心，需结合有效率判断，不能把丢失检测当成稳定。

## 黑色／浅蓝色物料诊断

在MaixVision中单独运行 `material_jitter_test.py`，无需其他项目文件。
补光始终关闭，默认 `COLOR=5` 测黑色，改为 `COLOR=6` 测浅蓝色。
设置与正式请求相同的 `ROI` 和 `ANCHOR`，只包含一个完整物料；白色采样框
必须完全位于物料表面，避开背景和高光，否则LAB统计没有参考意义。
预热2秒、采集10秒后结束，不打开串口，不发送动作。

检测条件与正式物料算法一致。绿色框为候选色块，红色框为被过滤色块，
黄色十字为唯一候选中心。输出有效率、稳定帧数、同时稳定且质量≥60的
可用帧比例、中心波动、质量值和采样框LAB均值的中位数。
`none`/`ambiguous` 为无候选／多候选帧数；`low_quality` 为唯一候选质量<60
的帧数；`area`/`clipped`/`outside` 为面积／ROI截断／锚点距离过滤的色块数。
诊断脚本的 `stable` 保留原2px、500ms条件；正式取料已放宽至8px，诊断结果不能直接等同于正式取料的稳定判定，仍须结合有效率和质量判断。
脚本只用于诊断，不会自动修改正式阈值；中心统计仅包含有效检测帧。

## 任意顺序取料（v1.0.6）

主控物料请求 selector=0 表示不限颜色；`values[6]` 为允许颜色位掩码，颜色N对应位N-1，0保持检测全部支持颜色。两轮路线首次对准发送selector=0、掩码63，支持任意颜色1～6；对准后夹取请求切换为当前指定颜色和对应单色掩码。相机逐色检测，仅返回识别区域内唯一目标；跨颜色阈值同时命中或多个目标均返回无效结果。selector=1～6保持指定颜色检测。

帧仍为30字节、协议版本1、CRC与token不变。物料结果 `values[0:5]` 仍为中心U/V、质量、宽、高；`values[5]` 新增实际颜色1～6，0表示未知；其余结果字段为0。取料主控必须取得已允许的实际颜色才能移动或夹取，旧相机的未知颜色不触发夹取。圆环结果保持原字段。

每批到取料区后，先用任意颜色物块的中心完整对准并停稳复检，不必等待该批任务的第一个颜色。对准完成后才切换为指定颜色请求，重新连续两次确认中心位于±30像素范围后夹取；三件取料均在横纵各±30像素范围内连续两次确认才夹取；偏差超出范围时用物料标定比例重新移动对准，停稳300 ms后重新请求相机复检，最多12次修正。取料及圆环／码垛观察水平位置统一为-770（较前版-720再回退5 mm，较原-500累计回退27 mm），其他观察坐标不变。每件取料观察姿态准备完成后，相机识别与升降轴下降50 mm同时进行；下降未结束时继续识别，结束后重新确认目标才夹取。完整任务严格按任务码颜色顺序夹取，非当前指定颜色不会触发夹取；物料依次放平台1/2/3槽。`route rawpick` 联调仍按绿/黄/浅蓝顺序夹取。现有相机协议及程序已经支持这些请求，无需更改相机程序。

本次须同步更新STM32固件和相机应用。MaixVision安装 `dist/maix-gongchuang_vision-v1.0.6.zip`；也可上传app.yaml列出的全部文件并运行main.py。取料稳定容差8px及标定比例仍须按实际抓取容差验证。
