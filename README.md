# 麦克纳姆轮串口点动测试例程

已加入地图两轮底盘路线、指定安全航点移动和 IMU 闭环旋转，支持蓝牙 `route auto 1|2 [rpm]` 连续跑完整路线、`route step 1|2 [rpm]` 逐点测试、`nav init 1|2` 初始化估计位置、`nav goto X Y [rpm]` 移动到安全航点、`turn L|R 90` 单独旋转和 `!` 急停。启动运动前先发 `arm`。首次使用请阅读 [ROUTE_TEST.md](ROUTE_TEST.md)。路线和导航位置均为速度积分估计，尚未接入地面定位、随机避障、扫码及抓取流程。

已增加同步距离测试、IMU 航向保持、单轮验向和四轮 CAN 查询。完整新增命令、接线及落地测试步骤见 [STRAIGHT_TEST.md](STRAIGHT_TEST.md)。原有命令保留；新版本运动期间会拒绝叠加运动命令，等待测试窗口结束或先停车。

本例程用于架空状态下检查 1～4 号麦轮电机的编号、方向和四轮联动。工程复用 `yyb_stm32` 的 STM32F407ZG 标准外设库、CAN 和 Emm_V5 驱动，不会修改参考工程。

## 硬件与通信

- 主控：STM32F407ZG，系统时钟 168 MHz
- 电机总线：CAN1，PA11(RX)、PA12(TX)，500 kbit/s
- 蓝牙命令串口：UART5，PC12(TX)、PD2(RX)，115200、8N1
- 麦轮电机地址：1、2、3、4；辅助机构诊断地址：5、6
- 舵机 2/3/4：PA1/PA2/PA3，对应 TIM2_CH2/CH3/CH4

HC-05 与核心板交叉连接并共地：

| HC-05 | STM32F407ZG |
| --- | --- |
| TXD | PD2 / UART5_RX |
| RXD | PC12 / UART5_TX |
| GND | GND |

HC-05 数据串口应配置为 115200、1 停止位、无校验，常见完整 AT 固件对应 `AT+UART=115200,0,0`。模块 RXD 必须使用 3.3 V 逻辑电平；若底板没有输入分压，不要输入 5 V 串口电平。

> 软件停止不能替代硬件急停。首次运行必须架空四个轮子，确认人员可以立即断开电机电源，并且不要直接运行完整整车流程。

## 使用方法

使用 Keil MDK 打开 `MecanumJog.uvprojx`，通过有线下载器编译并下载。配对 HC-05 后，在电脑或手机上打开对应的蓝牙串口。命令除 `!` 外均以回车或换行结束：

```text
arm       授权下一次运动命令，执行一次后自动取消授权
disable   停止并失能 1～6 号电机，无需 arm
motor N D 5/6号电机按方向0/1短点动，必须先 arm
auxmove N D R A 5/6号电机按相对距离移动，D单位0.1mm，必须先 arm
cancheck N 查询1～6号电机CAN状态并打印原始回包，无需 arm
servo N A 将舵机 N 移到电气角度 A，无需 arm
W / w     前进点动
S / s     后退点动
A / a     左移点动
D / d     右移点动
X / x     停止 1～6 号电机和舵机缓动，并取消授权
stop      停止 1～6 号电机和舵机缓动，并取消授权
!         无需回车，立即请求电机与舵机缓动紧急停止
help      显示命令帮助
nav init 1|2       以对应启停区初始化估计位置，要求空闲且 IMU 新鲜
nav goto X Y [rpm] 沿安全通道移动到指定坐标，速度10～120 RPM，默认60，必须先arm
nav status         查询导航有效性、估计位置和目标
route tune F L T [V]   空闲时设置纵向/横向比例、转向及横移上限；比例5000～15000，转速10～120 RPM
route scale N      兼容命令：仅设置横移比例
route rawpick 1|2 [rpm]  首轮原料区停车并依次夹绿、黄、浅蓝，必须先arm
pid get            读取导航/路线平移航向 PID 的 RAM 当前值
pid set KP KI KD   停车后设置航向 PID，三个参数均为实际增益的100倍
vision align material N  对准颜色1～6的物料，必须先arm且已完成视觉标定
vision scale material F R  空闲且arm后设置物料前后、左右比例；F/R为毫米/像素乘1000，范围50～2000
vision pick material N   底盘静止时识别颜色N，成功后执行单件夹取动作；必须先arm、初始化机构并确认当前姿态为(0,0,2700)
vision align ring N      对准物理圆环1～3，必须先arm且已完成视觉标定
vision scale ring N F R  空闲且arm后设置圆环N的前后、左右比例；F/R为毫米/像素乘1000，范围50～2000
vision pause/status      停止并接管/查询视觉状态
vision jog F R RPM       车体前/右方向各-20～20mm，10～30RPM，必须先arm
mech init H L T    人工确认当前机构姿态，单位为0.1 mm/0.1°，无需arm
mech pose H L T HR HA LR LA TS  移动到机构姿态（升降0～1500 ×0.1 mm），必须先arm
mech status        查询机构估计姿态
```

`nav goto` 接受地图范围内、车体按 300×300 mm 计算后仍满足净空的任意整数坐标。规划器会从当前估计位置接入静态安全航点图，并以水平或垂直安全线段到达目标；障碍区、边界净空不足或无法通过安全通道到达的坐标会返回 `ERR NAV:`。地图点击仍可吸附既有安全航点，也可在上位机输入精确坐标。导航运行期间约每 200 ms 输出一次 `NAV POS`；正常完成输出 `NAV DONE`。`stop`、`!`、心跳超时、CAN/IMU 故障以及其他手动底盘动作都会使估计位置失效，之后必须把车放回启停区并重新执行 `nav init 1|2`。

`route auto 1|2 [rpm]` 是仅控制底盘的完整跑图命令，依次经过二维码区、第一轮原料/粗加工/暂存、第二轮原料/粗加工/暂存并返回对应启停区。运行时约每 200 ms 输出 `ROUTE POS`，到达作业点输出 `ROUTE STAGE`，结束输出 `ROUTE DONE`；它不会执行扫码、抓取或其他机械动作。

`route rawpick 1|2 [rpm]` 是原料区联调命令。出发前确认机构实际位于水平0、升降0、转台270°、夹爪张开70°、平台1槽，并执行 `mech init 0 0 2700`；核对物料对准方向和抓取锚点后发送 `arm`、`vision scale material 640 673`，再发送 `arm` 和路线命令，也可在上位机“场地定位”页点击“路线取料联调（RAW_1 三件）”。未应用物料比例时路线拒绝启动，比例仅保存在 RAM。路线到达 `RAW_1`、完成转向后停车；依次等待绿(4)、黄(2)、浅蓝(6)。每件先将水平轴收至-500再拍照，相机确认物料中心连续至少500ms稳定且质量合格后，车辆按中心偏差限幅小步调整，停稳复检并连续两次进入误差范围才执行与 `动作组/夹取.json` 相同的抓取姿态，依次放入平台1、2、3槽。目标移动或识别不稳定时继续等待，不调整车辆或执行夹取；通信超时、机构或IMU/CAN故障会停止流程。第三件动作结束输出 `ROUTE RAWPICK state=DONE color=6 slot=3`，车辆仍停在 `RAW_1`，人工检查后发送 `route next` 或点击上位机“确认并继续路线”才继续；三件未完成时拒绝继续。`stop`、`!` 或故障后不能直接续行，须核实机构位置并重新初始化。对准只依据物料中心，不验证夹持结果；路线位置仍为积分估计。

`route mission 1|2 [rpm]` 是独立的两轮取放任务，保留上述两个联调命令的行为。启动前须在机构实际处于水平0、升降0、转台270°时执行 `mech init 0 0 2700`。通过上位机点击“开始两轮完整取放”时，会依次指令夹爪70°、平台26°，等待舵机到位，再以视觉页当前圆环2比例自动应用物料和圆环2比例，收到两次主控确认后才授权发送任务命令；直接用串口发送 `route mission` 时仍需手动完成这些准备。舵机角度检查只依据已发指令，不是实物位置反馈。路线在二维码点停稳1秒但不扫码；两轮均按绿(4)、黄(2)、浅蓝(6)取料。两次粗加工区先将水平轴收至-500，停稳后用圆环2视觉对准，再执行取自 `动作组/放置.json` 的三件放置动作，之后按对应位置取回到料盘；两轮暂存区同样先将水平轴收至-500，停稳后用圆环2视觉对准，成功后才用同一组三件放置姿态，第二轮将三个落点的升降深度从1480/1400/1450改为880/800/850（0.1 mm，数值减小即上升60 mm）。视觉微调位移按已发命令累计，机构回到水平0、升降0、转台270°后以15 RPM分步返回工位停车基准，再进入下一段。固件输出 `ROUTE MISSION phase=... station=...`；识别、动作、回位或传感器故障会取消任务，不能原地续跑。取回及暂存动作由现有姿态推导，必须先按台架分段验证电机方向、机械净空、夹持和急停，之后才可低速运行整圈；动作完成消息不代表实物取放成功。

若取料路线启动时报告机构姿态错误，先发送 `mech status`：`MECH INVALID` 表示需要在人工确认实际姿态后重新初始化；`MECH POS` 的 `h/l/t` 必须为 `0/0/2700`。舵机仍在运动时等待 `SERVO DONE` 后再试。不要为了通过检查，把未知实际位置直接声明为初始姿态。

导航/路线平移航向 PID 可在上位机“临时调试”页读取和写入，也可用 `pid get`、`pid set 200 25 12`。Kp 范围 0～10.00，Ki/Kd 范围 0～5.00，纠偏输出仍限于 ±12 RPM；写入时底盘及机构必须停稳，固件会回报当前值。参数只保存在 RAM，复位后恢复 2.00/0.25/0.12。平移期间约每 200 ms 输出 `PID TRACE target_cdeg=... actual_cdeg=... output_rpm=...`，上位机据此绘制目标/实际航向与纠偏输出曲线。原地转向和 `straight` 命令仍使用原有控制器。

`pid move A|D 2000 20` 用当前航向作目标，以导航航向 PID 限时向左/右横移并输出相同的曲线数据；需先 `arm`，时间 1000～5000 ms、速度 10 RPM 至当前横移上限。到时会停车，移动距离不作测量。上位机“临时调试”页提供左右按钮和时间、速度设置。

## 视觉微调

MaixCAM通过UART4连接：STM32 PC10(TX)接MaixCAM2 A22(RX)、PC11(RX)接MaixCAM2 A21(TX)，9600、8N1、3.3V逻辑并共地。部署 `camera_code` 整个目录并运行其中的 `main.py`。UART5仍用于上位机，USART2仍用于IMU。

自动微调按“停车识别—有限小步—停稳复检”执行；每轴单步最多20mm、累计最多100mm、最多12次，连续两次换算误差均不超过5mm才完成。相机帧使用30字节CRC协议和请求token，过期、重复、无效或非稳定结果均不能触发运动。`stop`、`!`、心跳超时、IMU/CAN异常和`vision pause`都会停止闭环。视觉或人工小步会使地图积分位置失效，之后必须重新`nav init`。

自动功能默认锁定。圆环可在上位机“视觉微调”页分别调整前后、左右毫米/像素比例，再点击“应用当前圆环比例”；主控确认后，该圆环以画面中心 `(160,120)` 为目标，按 `前后=-F×du/1000`、`左右=-R×dv/1000` 换算。两个轴的对应关系与符号来自圆环2的连续移动日志，尚未通过纯方向点动独立验证；当前未补偿轴间交叉影响。三个圆环的当前初值 `F=640`、`R=673` 都暂取自圆环2的粗略手动位移测量，并非圆环1、3的独立实测值，只适合低速小步验证；请先核对车体方向、急停和每步位移。物料比例也暂参考这组数据，须核实物料相机视角下的方向、比例以及画面中心是否对应实际抓取点；最终应按 [camera_code/README.md](camera_code/README.md) 做物料九点标定，必要时修改 `vision_config.h` 中的 ROI、锚点及交叉项。比例只保存在主控 RAM 中，重启后需重新应用。未应用时固件返回 `VISION ERROR reason=CALIBRATION_INVALID` 或拒绝启动取料路线。每个目标仍须保证相机能唯一识别。不得用零矩阵解锁。

单件原料夹取测试使用上位机“视觉微调”页选择颜色，再点“识别指定颜色并夹取”（或发送 `arm`、`vision pick material N`）。底盘须已停车且路线已退出；机构先人工放到 `动作组/夹取.json` 的初始姿态：水平0、升降0、转台270°、夹爪张开70°、平台位置1，并执行 `mech init 0 0 2700`。主控先把水平轴收至 -500（-50 mm），再请求相机稳定识别所选颜色；只有找到唯一、质量合格的目标才执行 `raw_pick_action.h` 中取自该 JSON 的固定单件动作表。测试时须人工将原料放在这套动作能夹到的位置；检测只确认颜色存在，不校验物料是否位于夹爪抓取点，也没有夹持力或抬起确认。`VISION STATE state=PICK_DONE` 只表示动作指令结束，须人工检查是否夹到。识别失败、超时、暂停或急停均不启动后续夹取；中断后机构位置失效，需人工核实再初始化。相机仍运行原 `camera_code/main.py`，无需重新打包。

地图移动距离仍是开环估算。`route_plan.h` 的 `ROUTE_FORWARD_SCALE` 与
`ROUTE_LATERAL_SCALE` 分别标定前后和横移。100 RPM、横移比例90%的6次中心点测试中，
车体右侧到场地右边界均值为103.9 cm（理论105 cm），因此默认横移比例改为90%；纵向
在取得实测数据前保持100%。当前路线和导航横移默认上限为60 RPM，转向默认上限为45 RPM；原90%横移比例取自100 RPM 测试，需按当前轮型和转速重新实测。更换地面、轮胎、负载或平移转速后必须重新实测。
上位机“临时调试”页可发送 `route tune F L T V` 同时调整纵向比例、横向比例、转向上限及横移上限；旧的三参数命令保持当前横移上限。设置仅写入 RAM，重启恢复默认值。
运动期间会被拒绝；横移上限也用于 `pid move A|D`。

机构命令中的 `H/L/T` 分别是6号水平位置、5号升降位置和转台角度，单位均为0.1；
`HR/HA/LR/LA/TS` 分别是水平转速/加速、升降转速/加速和转台速度（0.1°/s）。
水平范围为-122.0～65.0 mm，升降为0～150.0 mm，转台为0～360.0°；电机速度
10～2000 RPM、加速1～240，转台速度1～180°/s。移动期间约每200 ms输出估计的
`MECH POS`，完成输出`MECH DONE`。该位置没有传感器校验；停止、急停、心跳超时、
CAN故障或手动点动机构后会输出`MECH INVALID`，必须人工复位并重新执行`mech init`。

Qt 上位机选择 `mecanum_jog 文本协议` 后会每 250 ms 静默发送内部命令 `hb`。
固件收到首个 `hb` 后启用通信看门狗；若后续 1000 ms 未收到心跳，会停止 1～6 号
电机、停止舵机缓动并取消授权和路线，然后输出
`ERR: host heartbeat timeout; stopped`。从未发送过 `hb` 的手机或普通串口会话保持原行为。
该看门狗只能请求软件停车，不能替代断电急停。

舵机 2、3 的角度范围为 0～270°，舵机 4 为 0～360°。例如：

```text
servo 2 45
servo 3 90 1200
servo 4 180 1800
```

第三个参数为可选速度，单位是0.1°/s，范围10～1800；省略时使用1200，即120°/s。复位后 PA1、PA2、PA3 均不输出 PWM。每个舵机的第一条有效命令会直接建立该通道的软件当前位置；同一通道后续命令按指定速度缓动，并在到达后返回 `DONE servo=<编号> angle=<角度>`。`X`、`stop` 和 `!` 会取消正在进行的舵机缓动，并保持当前位置的 PWM 输出。

上电后发送一次授权再前进；运动命令会自动使能所需驱动器：

```text
arm
W
```

W/S/A/D 会消耗一次授权；再次发送 `W` 会被拒绝，必须重新发送 `arm`。测试结束可直接发送 `disable`。默认点动参数为 30 RPM、加速度 50、160 脉冲，四个电机使用同步位置模式启动。`line` 仅接受100、200、300、400或500 mm，`line/straight` 转速范围为10～120 RPM。

若要单独测试5号或6号辅助电机：

```text
arm
motor 5 0
arm
motor 6 1
stop
```

也可以按相对距离移动，正距离使用机构正方向，负距离自动反向。例如5号移动
20.0 mm、6号反向移动50.0 mm：

```text
arm
auxmove 5 200 30 50
arm
auxmove 6 -500 30 50
```

`auxmove` 参数依次为电机号、相对距离（0.1 mm）、RPM和加速度。5号单次范围
为-1500～1500，6号为-1870～1870，距离不能为0。固件没有位置传感器，范围限制
只约束单次命令，不能防止从当前位置撞到机械限位。

5、6号电机使用相同的保守点动速度、加速度和脉冲数，采用参考工程中单电机位置控制的立即启动方式，不发送同步启动帧。6号电机在参考工程中用于平推机构，首次测试必须确认机械限位并从安全位置开始。`X`、`stop` 和 `!` 均会停止1～6号电机。

若电机不转，先发送：

```text
cancheck 6
```

收到驱动器回包时，串口输出 `CAN RX motor N` 以及扩展帧 ID、DLC 和原始数据；300 ms 内没有回包时，输出 `ERR: motor N no CAN reply` 以及 STM32 CAN 的 `ESR/TSR` 寄存器值。`TX queued` 只表示固件已把运动命令交给 CAN 外设，不表示驱动器已经执行。

## 方向映射

| 车体方向 | 1号 | 2号 | 3号 | 4号 |

## 首次检查顺序

1. 只给主控和 CAN 收发器供电，确认串口出现就绪提示。
2. 接通电机动力后确认上电不会自动运动。
3. 未发送 `arm` 时发送 W/S/A/D 和 `motor 5 0`，确认均返回错误且电机不动。
4. 依次发送 `arm` 加 W、S、A、D，每次只观察一次低速点动并确认自动使能。
5. 分别发送 `cancheck 5`、`cancheck 6`，确认辅助电机地址和回包。
6. 舵机首次测试应卸除连杆，并从接近当前实际位置的小角度开始；舵机必须使用合适的外部电源并与主控共地。
7. 运动期间发送 `!`，确认 1～6 号电机停止且舵机停止继续缓动；测试结束发送 `disable`。
8. 若实际方向与表格不符，先核对电机地址、安装方向和驱动器方向配置，不要直接修改整车参考工程。

## 自动合约检查

在工作区根目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File mecanum_jog-main\mecanum_jog-main\tests\test_contract.ps1
```

该检查验证工程目标、共享源码路径、串口参数和方向表；它不能替代 Keil 编译或实机测试。

PC12/PD2 对应 UART5，只用于程序运行后的蓝牙命令通信。STM32F407 内置 ROM Bootloader 不支持 UART5，不要通过该 HC-05 连接烧录固件；烧录仍使用调试器或 PA9/PA10 上的有线下载连接。
